# R07 native peak publication retention (HW05 follow-up)

R06 withdrawn after real hardware regression. In 200 observations over 11.25s with the metronome bypassed, native left width was always 0, right 23–28; visual left/right exceeded the valid 132px bound in 95/98 snapshots respectively. Home callback rate 62.22Hz, own redraw requests 22.67Hz. Unsigned release subtraction could underflow and contaminate both packed channels; independent drawing bounds were also missing. The Mac mini R06 browser page was disabled. Corrected R06 source is retained offline only; it is NOT used by R07 and no corrected R06 image has been staged.

## Root-cause investigation

Exact frozen R03C SHARC meter primitive 0x2390 at PM 0x8da6a accumulates peak amplitudes and publishes via 0x8cbb8. The enqueue routine returns -1 when its ring is full, but the original meter clears PM(0,I8) unconditionally. Actual SHARC instruction simulation reproduces loss and verifies retaining the maximum across rejected reports and publishing it upon subsequent queue availability. An earlier failing single-sample test was caused by omitted circular-buffer base B1 in the fixture, not an established stock acquisition defect. Corrected tests cover all 16 positions, both polarities, circular mode, full/successful/non-reporting paths, repeated rejection and random normal path equivalence. No additional sample acquisition issue established.

The queue-full mechanism is a demonstrated stock code defect, not yet a proven explanation for the physical R05 missed clicks. The native 0x0002002a/1 event's exact association with this meter primitive remains unconfirmed. The proposed repair does not alter cadence, does not prevent multiple peaks from merging when congestion spans multiple beats, and does not synthesize clicks. The independent USB audio capture control failed because microphone permission was denied for the remote terminal. No preset settings were changed. To validate on hardware, compare R07's native peak vs TAP ledger across multiple stationary BPM windows and compare with R05 baseline (HW04 78/89 intervals high); look for delayed peaks as well as misses, and confirm original audio/UI features. If unsuccessful, trace the exact native source producer or obtain direct audio-window peaks.

## HW06 — user-reported R07 RAM run; native peak detection unchanged

The user reported R07 running, solid R05 bars restored, and continued dropped meter clicks. Live read-only editor confirmed preset 122 Super Lead, metronome model 181 slot 7 enabled, and the IOM4 ledger readable. **R07 and R05 deliberately share the same M4 binary and IOM4 signature. No independent runtime SHARC identity measurement was implemented.** The R07 bundle was byte-verified at staging, but that does not establish execution of its seven modified DSP instructions. Therefore label this *user-reported R07* and do not claim independently confirmed execution or a conclusive rejection of the queue-full mechanism.

800 paired 0x13/0x50 read-only observations, 23.6099 s: 43 TAP count increments; 42 complete beat windows; 37/42 with native output > -30 and exactly 37/42 with packed bar > 85px. Both output parameters 1 and 2 matched. R05 HW04 baseline 78/89 (87.6%); reported R07 37/42 (88.1%). No meaningful improvement. Missed TAP counts 74,78,83,87,91; highest native levels -56.83,-72.55,-71.84,-72.55,-72.64, respectively. Missed beats still contained 2–5 new native records. Only one transition in the observed output event sequence skipped more than one event count, making host polling alone an unlikely explanation for all five misses. The first 20 complete beats had 15/20 detected and mean 3.9 within-window new records; final 22 had 22/22 and mean 5.14. Earlier report gaps frequently ~200ms, later ~100ms. This phase-dependent native reporting resembles R05 HW04; it does not establish the upstream mechanism or physical acoustic continuity. Raw private capture `/tmp/io-r07-HW06-800.jsonl` is excluded from Git.

Next measurement experiment should independently record actual output waveform, preferably at the verified Main/USB 1/2 path, with timestamped peak windows and per-beat comparison, and independently identify runtime measurement revision. The stock DSP primitive 0x2390 is a peak accumulator, but 0x0002002a/1 has not been conclusively tied to it. The 0x25e6/0x25e8 processing routines add sample blocks into shared PM buses and are not independent per-sample peak measurements. The documented direct audio paths are Main 0x2aa8, USB writer 0x2aac ch0/1 Main and ch4/5 dry input, and the LPC M0 I2S/USB IN ring. Verify sampling/ownership and computational budget before modifying either DSP or USB processing. Mac mini recorder previously denied microphone permission; no workaround or settings change attempted. Do not introduce another cosmetic revision while root cause is unresolved.
