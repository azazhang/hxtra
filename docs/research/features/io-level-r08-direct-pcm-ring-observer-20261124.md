# R08: independent direct PCM observer (RAM-only)

## Why this is a separate measurement experiment

Reported R07 HW06 reproduced the native report loss: 37/42 high native/packed-bar beat intervals against R05's 78/89. The R07 runtime SHARC identity was not independently observable. R08 uses the exact original installed R03C SHARC instead of the R07 queue patch, preserves R05's existing renderer and native-key ledger, and measures actual digital audio separately. It is not a cosmetic revision, and the R05 solid bars are deliberately retained as the native-report comparator. The previously demonstrated stock queue-rejection defect remains documented, but has not been established as the cause of this issue.

## Source and transport audit (exact frozen image)

- `docs/research/sharc/usb-routing.md`: the USB output primitive 0x2aac provides the eight-slot stream: USB 1/2 Main, USB 5/6 dry inputs. The actual analog Main jack writer 0x2aa8 was separately physically identified in earlier HXtra research; its signal is not identical by definition to every USB monitoring or analog master-volume routing mode. Therefore R08 measures Main USB and dry USB channels, not an unconditionally calibrated analog jack level.
- Frozen M0 constructor 0x200042a8: context 0x20006338, descriptor pointer +0x30 = 0x20007a80, eight 32-byte descriptors, PCM base +0x1c = 0x2000b3f0. Ring initialization 0x20003adc sets consecutive 224-byte allocations, target lengths at descriptor +0x18. Stock USB IN completion 0x200038bc resets target lengths to 192 bytes (6 complete eight-word sample frames). M0 receive callback 0x20003390 stores completed length at +0x14, advances descriptor index at context +0x40, byte offset +0x46, and increments word count +0x50/+0x54. Its caller 0x20000bb0 writes the received word after the callback returns; its slot-zero synchronization is carried in bit 0. Direct observation reads complete descriptors only after the next descriptor has begun, excludes the active writer, and validates markers and exact completed-boundary count. Host USB activity may affect initialization and availability; R08 will report inactive or incomplete coverage rather than pretend samples were acquired.
- No M0 or SHARC instructions changed. R08 observes shared SRAM at fixed audited addresses in the M4 SPI receive callback. It never writes shared SRAM, any descriptor, audio, or routing. No microphone/recording permission workaround is attempted. It does not store or export raw audio: only counts and peak amplitudes.

## Implementation

`src/m4/io_level_r08_pcm_ring_observer.s` adds a bounded read-only observer; `0x1d` diagnostic has a distinct 128-byte IOR8 magic and seqlock-protected counters. M4 reads the producer count, index and offset twice, accepts only 192/224-byte completed buffers with exact fixed pointers, verifies all eight slot markers per frame, and checks the producer has not overwritten the earliest descriptor before committing. It rejects whole invalid batches without counting their levels, and resynchronizes with explicit skipped-word/reset/seed counters if the cursor laps the bounded scan range. Each successful batch contributes the absolute signed PCM24 peak on USB 1/2 and 5/6, and cumulative counts above approximately -30/-40/-50 dBFS. The host audit compares those cumulative counts with the independent TAP ledger and the native report/bar states; it also reports accepted sample rate and coverage. These counts preserve evidence of a short transient even when host polling misses its precise time. TAP boundaries are host-observed, not sample-exact; no optical/acoustic measurement is implied. `IOR8` verifies execution of the new M4 observer, and the sample-count progression/coverage verifies its measured source path; R08 has no new SHARC code to attest. Physical validity/coverage remain untested.

## Physical acceptance

Open `http://localhost:8765/IO-LEVEL-R08-DIRECT-PCM-RING-OBSERVER/` in Chrome on Mac mini after power cycle to permanent R03C; load RAM only. Leave guitar silent and metronome engaged; compare 800+ synchronized 0x1d/0x13/0x50 snapshots. Require IOR8 response, advancing producer and validated sample count, high coverage near nominal 48 kHz before attributing absent PCM peaks. Compare direct output high-sample counts in native-missed beat windows, inspect timing/boundary uncertainty and threshold sensitivity. If the PCM ring is inactive without a host audio stream, first determine the stock USB state; do not change user's global or preset settings. If observer significantly affects audio, freezes, or has insufficient ring coverage, stop and return to permanent R03C. Only after physical validation should the Home meters be driven by this source. R08 itself does not claim the dropped clicks fixed.

## HW07 conclusion (2026-11-23)

800 read-only IOR8/native/TAP samples verified R08 running. Over 23.1577 s, 51,888 observer callbacks saw a stationary PCM producer count/offset of zero in standalone operation. The USB PCM ring therefore cannot supply a standalone meter under this configuration. R09 instead samples the always-active SHARC graph paths and retains the native ledger solely as a comparator.
