IO-LEVEL-R01-NATIVE-RX-FRAME-PROBE

IO-LEVEL-R01: read-only capture of stock input/output meter messages. This RAM diagnostic extends the exact user-flashed R03C firmware without changing a single SHARC instruction, DSP audio model, DSP usage display, USB Monitor, existing GR meter, original R03C LED-synchronized click, preset or global setting. The stock SHARC Input block already runs native peak meter primitive 0x2390 and sends its measurement to the standard DSP event queue. This build records a complete, valid 256-word DSP-to-M4 receive frame exactly as the M4 sees it, via read-only HXtra editor command 0x4F.

This first-stage prototype records the real data. It does not yet draw input/output level bars. Their message offsets and interpretation must be established from real frames before assigning peaks to the left/right bars. After RAM boot, the host can read frames with tools/io_level_r01_native_frame_probe.py. Querying command 0x4F only returns the last fixed snapshot then arms a one-shot capture of the next valid native frame. The stock GR receiver runs as before. No incoming DSP frame is modified, and no new DSP code or new screen widgets run.

Current installed firmware must be exactly R03C (the image verified in the HWFLASH01 post-update QA). SHA256: 42c7bf82a5b0ce478aeedd4d6b8ca27c30cc87680ca2a84473613759cf68ba8b. R01 adds only two M4 hook edits and exactly 2392 bytes to the existing M4 application image. All other 14 archive entries, including the SHARC bootstream and output-writer/sidechain patches, remain byte-identical to the installed R03C. A static offline binary audit passed.

Opt-in hardware test, RAM only. The plan sends nine RAM regions with zero permanent eMMC writes and zero new SHARC overlay sectors. Two read-only identity checks compare the installed SHARC partition header and its first 1,023 full payload sectors against the exact frozen R03C image before RAM handoff. These checks cover R03C's distinct metronome DSP modifications. The current R03C persistent installation remains recoverable by a power cycle. The on-device behavior of this new M4 capture module has not yet been tested. If the device freezes, save the browser log and power-cycle to return to installed R03C.
