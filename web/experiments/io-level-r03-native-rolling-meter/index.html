IO-LEVEL-R03-NATIVE-ROLLING-METER-DIAG

IO-LEVEL-R03: two real-time Home-screen level bars based on the HX Stomp's own native DSP metering events. The user-booted R01 read-only capture verified actual eight-record native meter packets on physical hardware. R02's ten bins stayed visually static. R03 retains the validated 44-word native event stream while providing 132-pixel resolution and read-only rolling diagnostics over command 0x13. The DSP peak collector is unchanged. R03 leaves the 512 KiB SHARC bootstream, metronome, USB Monitor, GR meter, DSP Usage Display, presets and global settings byte-identical to permanently installed R03C wherever applicable.

Two experimental high-resolution horizontal bars: the left green bar uses the first native meter pair (IDs 2,5); the right blue bar uses the last native meter pair (IDs 1,5). Each is 132 by 5 pixels in the Home-screen gap above the bottom labels (x 24 or 164, y 113–117). The scale covers native readings −90 to 0 dB at 1-pixel resolution (approximately 0.68dB per pixel), with amber/red near full scale. The stock DSP publishes meter events at its native cadence, and the bars clear after prolonged missing packets. Other native packet formats are ignored so that stale DMA buffer contents cannot masquerade as a new signal value.

Physical Input/Output assignment remains to be validated. The first pair is temporarily drawn on the left and the last pair on the right. The physical or USB input and Main/Send output assignments have not been established by calibrated measurements; this build records all eight native values so the mapping can be established from actual signal activity. This is an experimental display to establish that mapping from a controlled signal, not a calibrated two-bus meter ready for permanent installation. The existing R01 read-only capture command 0x4F remains; new read-only command 0x13 reports how many native meter packets actually reached the M4, whether bar state changed, and the most recent eight native floating-point level values. This allows meter-source validation while the metronome or instrument plays.

The candidate adds exactly 960 bytes to the R01 M4 application with exactly three new M4 hook points (RX listener, Home painter, read-only editor diagnostic registration). All 14 non-M4 firmware entries are identical to the installed R03C image SHA256 42c7bf82a5b0ce478aeedd4d6b8ca27c30cc87680ca2a84473613759cf68ba8b. The R03 HXF SHA256 is 1f5852eea09a8ec6816231d0e993ca33194f1a82d7cb27216e75d14c41f89bc8. No SHARC code, bootstream records, USB routing, saved setting, or footswitch function has been changed by this build.

Opt-in RAM experiment ONLY. Do not flash with Line 6 Updater. Power-cycle out of the currently running R02 RAM experiment to the permanently installed R03C first. The preflight requires 9 RAM regions, 2 read-only eMMC identity checks covering the frozen R03C SHARC partition, 0 eMMC overlays, and writes=RAM. Press Run yourself, choose the USB device when prompted, and observe the two bars while playing a known signal through the input and output paths. R02 was physically booted and displayed a stationary bar; R03 has not yet been physically tested. If it freezes, save the browser log, power-cycle and the permanently installed R03C returns.
