IO-LEVEL-R04-FULL-NATIVE-EVENT-LEDGER

IO-LEVEL-R04: read-only ledger of all native DSP meter events. This is a data-source identification experiment. The two existing Home-screen bars keep their R03 trial source mapping and may still show minimal motion. The user-booted R01 read-only capture verified actual eight-record native meter packets on physical hardware. R02's ten bins stayed visually static. R04 measures every complete native event record, including small 9/14-word messages discarded by R02/R03. This is a targeted measurement diagnostic. The old 132-pixel trial bars remain provisionally mapped and may stay static. The DSP peak collector is unchanged. R04 leaves the 512 KiB SHARC bootstream, metronome, USB Monitor, GR meter, DSP Usage Display, presets and global settings byte-identical to permanently installed R03C wherever applicable.

Two experimental high-resolution horizontal bars: the left green bar uses the first native meter pair (IDs 2,5); the right blue bar uses the last native meter pair (IDs 1,5). Each is 132 by 5 pixels in the Home-screen gap above the bottom labels (x 24 or 164, y 113–117). The scale covers native readings −90 to 0 dB at 1-pixel resolution (approximately 0.68dB per pixel), with amber/red near full scale. The stock DSP transmits different native event lengths. The unchanged trial bars still use the complete 44-word packets; the NEW ledger separately counts all complete 5-word records inside other native packet lengths.

Physical Input/Output assignment remains to be validated. The first pair is temporarily drawn on the left and the last pair on the right. The physical or USB input and Main/Send output assignments have not been established by calibrated measurements; this build records every event object/parameter key with min/max so the mapping can be established from actual signal activity. This is an experimental display to establish that mapping from a controlled signal, not a calibrated two-bus meter ready for permanent installation. The existing R01 read-only capture command 0x4F remains; read-only command 0x13 now returns a 640-byte rolling ledger of all complete five-word native records, including short incremental packets: each distinct object/parameter key's observation count, latest value, minimum and maximum since R04 boot. There are 24 slots, with all native values labeled by object/parameter ID so their actual physical Input/Output identity can be checked before implementation.
