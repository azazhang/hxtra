IO-LEVEL-R05: two independently responsive native meter candidate bars. R04's physical guitar-only capture with Metronome block bypassed showed a strong guitar-responsive native value at 0x00020002 / parameter 3, while both guitar and metronome activity strongly changed another value at 0x0002002a / parameter 1. The two records varied independently while the prior R02/R03/R04 trial bars read the wrong native family.

Left green bar: provisional Input candidate 0x00020002 / 3 (upstream guitar-responsive; physical input jack identity not yet proven). Right blue bar: provisional Output candidate 0x0002002a / 1 (tracks guitar and pulses aligned with TAP/metronome; Main/Send/USB destination not yet proven). Each bar is 132 × 5 pixels at x24..155 or x164..295, y113..117. Real native values are mapped over −90 to 0 dB-like units at approximately 0.68 dB/pixel. Updates are independent for each source, with up to ~23 Home refreshes/sec, and a two-second stale expiry per bar if its native source stops reporting. Neither value is currently calibrated against external audio hardware.

The existing native event ledger is preserved. Read-only editor command 0x13 reports 24 keyed object/parameter rows with last value, min, max and count in exactly 640 bytes. The R01 read-only raw capture command 0x4F and R03C metronome command 0x50 are unchanged. The 44-word native meter packet is still counted and recorded, but its wrong-family values are excluded from the new two-bar display. No new SHARC code or DSP side processing is added.
