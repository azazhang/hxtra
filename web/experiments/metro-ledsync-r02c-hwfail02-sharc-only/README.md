# METRO-LEDSYNC-R02C-HWFAIL02-SHARC-ONLY

This is a separate, **user-initiated** RAM-only startup-isolation test following R02C's confirmed freeze. It modifies **only Entry 2** (SHARC bootstream) relative to the exact installed HXtra v1.2.1 donor, SHA256 `96ac133e094c75f2701226fc7cf3fca4c04b19b91aa34785e646d919979b88c0`. The original donor M4 Entry 0, DSP Usage Display, USB Monitor and the other 13 entries remain identical. The SHARC click shim is identical to the one that existed in the failed R02C firmware, but it receives **no external marker** because the original M4 has no metronome event bridge. Therefore this is exclusively a startup-isolation test, not an audio LED synchronization verification.

Reproduce using `PYTHONPATH=tools:tools/sharc python3 tools/build_metro_r02c_hwfail01_ablations.py` after checking the input donor identity. The resulting HXF is `build/startup-isolation/METRO-LEDSYNC-R02C-HWFAIL01-SHARC-ONLY/METRO-LEDSYNC-R02C-HWFAIL01-SHARC-ONLY.hxf` (SHA256 `3aa8d41b6d925272a00db2a16f2c112d1399f0adde70131ee3f78d47c09cf2ce`). Copy the resulting `regions` directory adjacent to the versioned `index.html` and `ramrun.js`, along with unmodified `tools/ramboot/firmware-ramboot.dfu`. The plan hash must be `6da7a6dc8fb5bbb139e716b60ebca2de8a689bf2425fa068a91b9d5bf76d473a`, nine RAM regions, 11 Entry2 overlay sectors, one donor-reference read-only eMMC check, and `writes='ram'`. The browser preflight enforces the changed entry and overlay sector count. It uses the same working WebUSB RAM runner as the successful unmodified-donor positive control.

Mac mini local URL: `http://localhost:8765/METRO-LEDSYNC-R02C-HWFAIL02-SHARC-ONLY/`. Only load after confirming the successful unchanged-donor positive control, and power-cycle out of any other RAM image before starting.
