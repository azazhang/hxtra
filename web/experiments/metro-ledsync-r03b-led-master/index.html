METRO-LEDSYNC-R03B-LED-MASTER

R03B: actual FS3 TAP LED-driven Metronome audio (experimental). This is the first combined, exact-installed-HXtra-v1.2.1 donor-based M4-to-SHARC LED master candidate using the R03A kernel's physically verified in-place 142-word SHARC process record. All original 201 SHARC boot records remain in the same order, with the same lengths and addresses. Entry2 stays 524212 bytes. The exact donor M4 is altered only at four audited hook sites: post-filter FS3 LED egress, Metronome bypass, diagnostic registration, and the existing SPI TX callback. Other installed DSP/UI code, DSP Usage Display, USB Monitor, menus, settings, presets, and saved configuration are untouched. Exact installed donor SHA256: 96ac133e094c75f2701226fc7cf3fca4c04b19b91aa34785e646d919979b88c0.

The M4 publishes real final TAP LED ON commands into SPI words240/241 as a 32-bit counter and its full bitwise complement. The SHARC validates both before issuing any click; a failed or torn pair cannot trigger a beat. The M4 suppresses OFF->ON reversals shorter than 20ms: the previous physical R01 trace found six such reversals (shortest 1.870ms) during repeated BPM knob changes. These reversals may not be optically perceptible; this filter is an explicit testable engineering assumption. Bypass/re-engage causes the next accepted LED ON to trigger the accented downbeat. Audio is scheduled on the next 16-sample SHARC block after the validated SPI event. Absolute optical-to-audio latency and hardware phase stability are not yet measured.

Unproven experimental firmware — user-initiated RAM load only. The real R03A SHARC-only baseline booted and played as original HXtra; the new M4 sender and combined audio synchronization have passed offline Unicorn/ssim tests but have never been run together on hardware. The plan overlays four RAM-only sectors: the revised SHARC CRC metadata at on-card sector 0x8802, two changed metronome PM payload sectors and one copy of the zero-padded unchanged final partial sector. No eMMC writes. The WebUSB handoff proves transfer CRCs, not a successful physical startup.
