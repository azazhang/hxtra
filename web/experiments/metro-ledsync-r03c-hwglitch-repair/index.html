METRO-LEDSYNC-R03C-HWGLITCH-REPAIR

R03C: ordered TAP LED events, verified double-click repairs and read-only latency probe. This is the experimental successor to physically booted R03B, which the user reported sometimes produced two clicks close together at a stationary BPM and a perceptible audible delay after the visible FS3 TAP LED. The two previous software defects were independently reproduced with actual SHARC instructions: a complete but stale SPI event pair could retrigger a click, and transient invalid no-TAP frames could reactivate the donor free-running click clock.

The new SHARC kernel rejects duplicate/older 31-bit event counts, independently validates the complementary SPI pair and accepts genuine re-engagement epoch advances. It retains the original 142-instruction metronome LDR record with all 201 original SHARC boot descriptors and unchanged Entry2 size 524212. An exact-power-of-two gain rescaling saved instruction space while keeping the original click audio bit-for-bit identical in emulator parity tests. The M4 publisher holds its latest valid count during transient FS3 TAP visibility drops for up to 4,600 SPI frames (roughly 2 seconds at the measured 2,300 frames/s). Sustained non-TAP mode resumes the native donor metronome clock. Existing 20ms LED dark-interval filtering remains unchanged.

The perceptible LED-to-audio delay has NOT been resolved. R03C adds a read-only native microsecond measurement from the accepted post-filter M4 FS3 LED command to its first M4 SPI transmission. After a hardware boot it can be queried using tools/metro_led_r03c_probe.py, command 0x50. This measurement does NOT include SHARC reception, audio output buffering, or actual LED optical latency. A later independent optical/audio recording may be necessary to quantify and compensate audible delay. Do not interpret an M4 transmit checksum as a DSP acknowledgement.

Firmware is derived strictly from the user's installed HXtra v1.2.1 HXF SHA256 96ac133e094c75f2701226fc7cf3fca4c04b19b91aa34785e646d919979b88c0. Only four audited original M4 hook sites and one existing SHARC metronome PM record are altered; the other 13 L6IA entries remain byte-for-byte identical. Installed DSP Usage Display, USB Monitor, all other models/UI features, presets and global settings are retained in the candidate package.

Experimental user-initiated RAM load only; hardware behavior is unverified. Nine RAM regions, four RAM-only eMMC redirect sectors including corrected SHARC CRC metadata at 0x8802, and one read-only donor-reference checksum. There are NO permanent firmware/eMMC writes. R03B's physical boot and audio complaints are separate evidence and do not prove R03C will boot or correct perception.
